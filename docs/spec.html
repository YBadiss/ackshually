ackshually

Settle a board-game rules dispute mid-game. Ask about the rulebook PDF, get the ruling at once, and swipe through the highlighted evidence when someone pushes back.

1 · Product

The moment

Mid-game, someone asks "wait, can I do that?" and the table is waiting. Speed and trust beat depth. Anyone at the table may ask, and the phone often gets handed to the skeptic.

Principles

  1. Ruling first, proof on demand. The verdict shows immediately; the evidence is one swipe away.
  2. The source is the star. The rulebook page stays on screen; the app never hides what the rule actually says.
  3. Never confidently wrong. Every answer is labeled Stated, Inferred or Not covered. External sources are always labeled.
  4. Never block the table. No waiting to upload, prepare or confirm before asking.
  5. Neutral referee. Verdicts are plain and fair; personality lives in the name, labels and empty states.

In scope now

  • One PDF per game, uploaded by the user.
  • Ask by typing or push-to-talk. Answers on screen, optional read-aloud.
  • Branches when the outcome depends on something unstated.
  • Conversation context per session; sessions saved per game, on device.
  • Web fallback (BGG / Reddit) when the rulebook doesn't settle it.
  • 👍/👎 per answer; export a game's data as JSON.

Not now

  • Several PDFs per game (expansions, FAQs). The data model already allows it.
  • Asking clarifying questions.
  • Curated rulebook library.
  • Remembering past rulings as house rules.
  • Server, other users, Android, iCloud sync.

2 · Screens

Milestone in the tag. Gestures in bold. Blue marks on the mockups show the gesture being described.

S1 · My Games M3

List of games (cover, name, sessions or preparation progress) and an "Add a rulebook PDF" field.

  • Tap a game → viewer, resumes the last session.
  • ＋ → iOS file picker / share-sheet import → S2.
  • Swipe left → Export · Delete.
  • Before M3 the app opens straight into the last PDF.

S2 · New game, preparing M2 · OCR in M3

  • The PDF is readable and askable immediately.
  • A thin progress line appears only if pages need OCR (scans, outlined text), then disappears.
  • Until a page is prepared, highlights on it fall back to showing the whole page.

S3 · Asking M2

  • Type and send: always available, for private questions.
  • Hold 🎙: live transcript, release to send, slide left to cancel.
  • Tap 🎙: dictation; review and edit before sending.
  • The PDF can be browsed freely (pinch, scroll) at any time.

S4 · Answer arriving M2

The sheet rises as soon as the first words arrive and fills in this order:

  1. Restated question ("3 energy + a Battery, at end of turn"). If it's wrong, Stop and rephrase without waiting.
  2. Verdict + proof line (placeholder text until they arrive).
  3. Step 1: the PDF jumps to the page, zooms and highlights. Later steps keep loading.

Between send and the first token the ask field shows Reading the rulebook… with the question and Stop; the sheet rises on the first token.

S5 · The answer sheet M2

Two layers, no Back/Continue buttons:

A system sheet with three detents (collapsed, medium, large); the PDF stays usable under it up to medium. No Back/Continue buttons:

  • Answer header, fixed while stepping: text hierarchy, no chips. Bold verdict, then one secondary proof line (checkmark.seal Stated in the rules · p.12, p.14). Close (or Stop while streaming) top-right.
  • Step cards: a horizontal shelf of system cards; the next card peeks from the edge, which signals "swipe". Caption = step title + page, then one or two sentences. Page dots below.
  • Branch rows under the cards (Without a Battery … Discard all 3 ›), grouped like Settings.

S6 · Stepping M2

  • Swipe left / tap the right peek → next step. The PDF follows the card: page turn, zoom, highlight.
  • Swipe right / tap the left peek → previous step.
  • Last card: the result + thumbs up / down, with the follow-up field under it.
  • A step can cite several passages (pager "1 of 2 ›" on the PDF) or a figure (box outline; if no usable box, the whole page + "see the diagram, lower half").

S7 · Show the skeptic M2

  • Drag the sheet down → page near full-screen, the collapsed detent keeps the verdict + proof line (with pages) at the bottom.
  • Drag up to restore.

S8 · Inspect freely M2

  • Pinch / pan the PDF at any time to read the surrounding qualifications. Tapping the PDF never changes steps.
  • A Back to Step N glass button re-centers on the highlight.
  • Double-tap: evidence zoom ↔ full page.

S9 · Full answer M2

  • Drag the sheet up (large detent) → restated question, header, then grouped rows: Steps (tap to jump), If…, Assumes, Was this right?, follow-up.
  • Tap a branch row → the header shows that branch's verdict and the step cards switch to the branch's own steps (branches[].steps); a "Main Answer" row returns.
  • Wide screens (iPad, Mac, phone landscape): the same content in the standard inspector column beside the PDF; a toolbar button shows/hides it.

Screenshots of the built app: m2-screenshots/restyle/ (they supersede the mockups' visual treatment).

S10 · Not covered → web M4

  • Triggered when the rulebook answer is Inferred or Not covered. The rulebook part shows first; a "Searching BGG & Reddit…" card fills in after.
  • Web findings are bordered step cards, never PDF highlights: site, date, author role (designer / publisher / community), quote, link.
  • If a source disagrees, the rulebook verdict stays in the header and the card says ⚠ Designer disagrees (strong) or ⚠ Community disagrees (soft).

S11 · Feedback M3

  • 👍 is saved silently.
  • 👎 → one-tap reason (wrong verdict, missed exception, wrong highlight, wrong page, too slow, other), optional step, optional note.
  • ⋯ → Export game: one JSON with all sessions, questions, full model outputs, timings, tokens and ratings.

S12 · Sessions M3

  • ⋯ → Sessions: past questions per game, grouped by night. Tap → reopens that answer.
  • New = new game night; clears conversation context.

Read-aloud M4

No screen. Off by default, toggled in ⋯. Speaks the restated question and verdict only. Any tap stops it.

3 · Visual style

Direction (2026-11-21): native iOS, warm. Use standard components and let the warm palette tint them. Reference: design/native-ios.html. It overrides the visual treatment of the S-mockups above (which still define layout and interactions) until they are redrawn.

  • System components first: system sheet with detents, navigation bar with a standard ⋯ menu, inspector on wide screens, grouped rows (like Settings), SF Symbols, native page/scroll behavior, Liquid Glass for controls floating over the PDF (ask field, Back to Step, passage pager, close/stop). No custom pills, outlined chips or boxed web-style cards.
  • Text hierarchy instead of decoration: bold verdict (title3), then one secondary line of proof ("checkmark.seal Stated in the rules · p.3, p.4"; inferred: exclamationmark.triangle, not covered: questionmark.circle). The restated question shows only while waiting and in the expanded view. "Demo answer" is a footnote in the expanded view and a note in the ⋯ menu, never on the verdict.
  • Step cards keep the peek, styled as system cards (App Store / Music shelves): rounded, no borders or shadows; caption = step title + page.
  • Branches, steps, feedback are standard rows with chevrons / values.
  • Warm, but restrained: brick red as the app tint, warm-tinted bars, sheet and grouped backgrounds, warm highlighter on the PDF. Not plain white; not beige everywhere.

4 · Answer contract

What the model returns. Field order is streaming order: it is what lets S4 show the restated question, then the verdict, then step 1. Branches and assumptions come after the main steps so they never delay step 1.

{
  "restated_question": "You have 3 energy and a Battery at end of turn.",
  "verdict": "Keep 2 energy, discard 1.",
  "confidence": "stated | inferred | not_covered",
  "steps": [
    {
      "title": "General rule",
      "text": "Unused energy is discarded at end of turn.",
      "evidence": [
        { "page": 12, "quote": "discard all unused energy", "box": null }
      ]
    }
  ],
  "branches": [{
    "condition": "Without a Battery",
    "verdict": "Discard all 3.",
    "steps": [{ "title": "General rule", "text": "…", "evidence": [ … ] }]
  }],
  "assumptions": ["The Battery is already in play."],
  "needs_web": false
}

box is {x, y, w, h} normalized 0–1, used for figures. title (2–4 words) is the card caption. A branch carries its own steps (usually one) so the cards can switch to it (S9). Both are required by the structured-output schema and optional when decoding, so older answers still load (no title → "Step N"; a branch without steps → one card).

Placing a highlight, in order

  1. Match quote to the page's words as a continuous passage (PDF text layer, or OCR words for scanned/outlined pages) → word-level highlight.
  2. Layout-tolerant match: multi-column pages and text over art scramble the text layer's reading order. Find the region where the quote's words cluster by position instead of requiring them in sequence; if that fails, OCR the page with Vision (visual reading order) and retry. M1: all 4 misses were this case, not model misquotes.
  3. Repair call (background, cheap model): "this quote wasn't found on p.N; here is the page text; return the exact passage." The highlight appears a moment later.
  4. Otherwise draw box if it passes sanity checks.
  5. Otherwise show the whole page and log a miss.

Evidence mode: quotes written by the model (json). M1 compared it with Claude's native PDF citations, which gave lower accuracy, fewer clean highlights and no figure boxes.

5 · Architecture

Core/    Swift package, no UI (macOS + iOS)
         models · AnswerProvider protocol + ClaudeProvider · streaming field parser
         quote matcher (fuzzy) · box checks · [M3] Vision OCR prep · [M4] web fallback
evals/   bench CLI on Core: question sets, runs, kept results
App/     [M2] SwiftUI app: PDFKit viewer, answer sheet, SwiftData storage
  • The app and the evals share Core, so benchmark numbers reflect the app.
  • Whole PDF + question + conversation in one streamed request; the PDF is prompt-cached with a 1-hour TTL (mid-game questions are often 5–60 min apart; a cache write costs 2× input instead of 1.25×, which pays off from the third question).
  • Data model: Game → [Document], Game → [Session] → [Answer]. Everything on device.
  • API key: Keychain in the app, ANTHROPIC_API_KEY for the evals. The app calls the API directly; no server yet.
  • Step carousel: horizontal ScrollView + .scrollTargetBehavior(.viewAligned), side margins for the peek, .scrollPosition(id:) drives the PDF. Fallback: TabView(.page).
  • Figures: v1 uses the model-proposed box. If boxes score badly, use Vision-detected candidate regions and let the model pick one.

M1 tests five assumptions

  1. One call with the full PDF answers correctly with usable evidence (target ≥90%).
  2. Verdict + step 1 arrive fast when streamed (median ≤5 s, 90% ≤10 s).
  3. Quotes land on the right words (≥90% of highlights).
  4. Model-proposed boxes land roughly right on figures (Azul).
  5. Cost per question is tolerable, and caching makes follow-ups cheap.

Result: 1 ✅ (Sonnet 27/28, Opus 28/28) · 2 ❌ (step 1 median 6.0 s; the PDF size sets a ~4–5 s floor) · 3 ✅ (94–97%; misses were our text extraction) · 4 ⚠️ barely exercised · 5 ✅ (Sonnet ~$0.28 for 20 questions). See m1-report.md and eval results.

Speed experiment (alongside M2): select the relevant pages locally and send only those; success = step 1 median ≤5 s with no accuracy loss.
